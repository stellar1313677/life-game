## 2026-08-08（追加：動物真的要換圖，不只是搖擺）

上一輪（見下方「三個測試回饋」那則）把動物移動改成「三層結構 + 上下搖擺」，使用者測完還是覺得怪，講得更清楚：**要有 2、3 張圖片互相切換**，不是靠緩動硬撐。完整內容見 [`docs/animalsbug.md`](./animalsbug.md#2只有搖擺不夠動物移動還是很怪異要真的有-23-張圖片互相切換)。

問題出在我上一輪理解錯了：「沒有走路動畫」是字面意思，要真的換圖（像老遊戲 2 幀走路 sprite），連續緩動振盪不管怎麼調參數，看起來都還是「同一張圖在抖」，不是「腳在走路」。

這次整個動物視覺從單一 emoji 改成程序化 SVG 剪影，跟卡片上的武器圖示同一套風格（`currentColor` 線稿），並且真的做 2 幀切換：

- 5 種動作原型：`walk`（四足走路）、`fly`（振翅）、`swim`（尾鰭擺動）、`crawl`（蝸牛爬行）、`flicker`（螢火蟲明滅），各手繪 2 幀，共用身體輪廓只換動的部位（腳/翅膀/尾鰭/觸角），這樣切換時身體不會整個跳動
- 換幀速度綁定先前算好的搖擺週期（大隻慢速動物換幀慢，小隻快速動物換幀快），用 `setTimeout` 遞迴排程做硬切換（直接換 `innerHTML`，不加 transition），螢火蟲群改用不規則亂數間隔模擬自然明滅
- 動物離場時記得把換幀的計時器清掉，不留殘留計時器

驗證：完整瀏覽器 `JSDOM.fromURL` 測試這次在這台機器上會卡住不回應（懷疑是環境問題不是程式碼問題），改用手動 stub 一個最小 DOM 環境直接跑 `Animals.init()` → `spawnOne()`，確認一般動物跟螢火蟲群兩條分支都正確排入對應數量的計時器、都沒有拋出例外；`Data.renderAnimalFrame()` 產生的兩幀內容也直接用 Node 確認過真的不同。兩幀切換的節奏「感覺對不對」還是要請使用者實際看一次瀏覽器。

## 2026-08-08（追加：修 bug，第二輪才修對）

**修好**：「心情日誌」面板打開後空白（只有標題和關閉按鈕，連零筆時該有的「還沒有紀錄。」都不見）。完整調查過程見 [`docs/appearancebug.md`](./appearancebug.md#1心情日誌面板打開後是空的只有標題和關閉)（原檔名 `bug.md`，後來拆成外觀／動物兩份，見 2026-08-08 較晚的追加項），這裡記結論，包含第一輪診斷錯在哪。

**第一輪（錯的診斷）**：以為是瀏覽器快取吃到舊版 `ui.js`，幫 `index.html` 全部本機資源加了 `?v=2` 版本查詢字串。用 jsdom 模擬過真實操作流程，DOM 內容都是對的，所以當時判斷「邏輯沒問題，是快取」。**推上去之後使用者回報問題依舊**，代表這個診斷是錯的。

**第二輪（真正根因）**：請使用者開 F12，兩個證據直接鎖定問題：
1. Console 沒有任何我程式碼丟出的紅字錯誤 → 排除 JS 例外，代表問題在渲染層而非邏輯層
2. Elements 面板看到 `<div id="daylog-panel" class="overlay" hidden>` 旁邊掛著 DevTools 的藍色 **`flex`** 徽章 —— 代表這個元素明明有 `hidden` 屬性，運算後的 `display` 卻是 `flex`，`hidden` 根本沒生效

**真正原因**：`hidden` 屬性能不能隱藏元素，全靠瀏覽器內建一條很低優先度的 `[hidden]{display:none}` 規則撐著。`.overlay{display:flex}`（這個 class 全站 7 個 modal 共用）跟 `.ceremony{display:flex}` 選擇器優先度跟 `[hidden]` 打平，author stylesheet 蓋過瀏覽器預設樣式，`hidden` 屬性形同虛設。這不只是心情日誌一個元件的問題，是全站所有靠 `hidden` 控制顯示又自己設了 `display:flex/grid` 的元件共通的 bug，只是 `daylog-panel` 剛好是 DOM 順序最後一個 `.overlay`，疊在最上層，最先被注意到。

**修法**：`src/css/style.css` 開頭加一條全站保底規則：

```css
[hidden] { display: none !important; }
```

一次修掉全部現在跟未來的同類元件，不用一個一個補。用 jsdom 讀 `getComputedStyle` 逐一比對修前修後的 `display` 值確認修好（見 `appearancebug.md` 的完整輸出對照）。

**這次真正學到的**：純看 DOM 內容（jsdom）抓不到「內容有寫進去、但畫面上看不到」這類 CSS 排版問題，因為 jsdom 不做真的 cascade 運算；遇到這種症狀要換成能看 computed style 的工具（真瀏覽器 DevTools 最直接）。第一輪診斷錯了就承認、留紀錄，不要硬凹。

## 2026-08-08（追加：三個測試回饋）

使用者實際測試後回報三個問題，逐一處理，完整內容見 [`docs/appearancebug.md`](./appearancebug.md)（#2 skin 圖示、#3 已完成可回爐）與 [`docs/animalsbug.md`](./animalsbug.md)（#1 動物走路動畫）：

1. **神器 skin 沒有顯示** —— 查了資料層完全沒問題（`skin_id`、名稱都對），問題是根本沒把 `data.js` 裡定義好的 `glyph` 欄位拿去畫成圖案，卡片一直以來就只有一行文字，沒有圖示。補了一套程序化 SVG 線稿圖示（10 種 MODERN skin 各一組簡化 path，用 `currentColor` 上色，自動吃品質色），接到卡片、任務詳情、鍛造儀式三個地方。仙俠/魔法分支的圖示還沒畫，先落到通用 fallback，等那兩個分支開放時要記得補。
2. **背景動物沒有走路動畫，移動很怪異** —— 原本只有一層「筆直等速平移」，難怪任何動物看起來都像貼著尺規滑過去。改成三層結構（位移／搖擺／面向鏡射各自獨立），加了會依動物體型（大隻慢的搖擺幅度大週期長，小隻快的搖擺小週期短）調整的走路/游動搖擺動畫。順手把舊的 `translateX + scaleX` 疊在同一個 `transform` 裡的寫法拆開，避免以後改動時因為兩種效果耦合在一起而出錯。
3. **已完成的神器也要能回爐** —— 這不是 bug，是使用者想要的行為調整。SDD §9.2 原本預設完成品不給回爐（要嘛不開放、要嘛藏在設定深層），但文件本身留了「或需進入設定深層才可執行」的彈性；使用者測試時明確表示想直接回爐、不想多一層關卡，尊重這個決定，直接把任務詳情面板的回爐按鈕對 COMPLETED 狀態也打開，跟其他狀態共用同一套確認文案，沒有另外加警語。

驗證方式：資料層跟 DOM 結構用 jsdom 全部走過一次確認（skin 圖示真的有 `<svg>` 元素、回爐按鈕在 COMPLETED 狀態下真的存在），CSS 動畫的「感覺對不對」這種主觀節奏問題沒辦法用腳本斷言，還是要請使用者實際在瀏覽器看一次。

## 2026-08-08

**依 [`docs/sdd-v2.md`](./sdd-v2.md) 完成 MVP 範圍（§15.2）的實作**，專案從純骨架（`index.html` 只有一句佔位文字）變成可運作的完整前端應用。

### 做了什麼

- 全站改為傳統 `<script>`（非 ES module）架構，維持「直接雙擊 `index.html` 就能跑」的零建置需求：
  - `data.js` — 詞條庫（50 個形容詞 + 7 個奇物）、skin 表、動物表、品質色、難度機率表、開場故事，全部照 SDD 表格逐字搬
  - `state.js` — `localStorage` 持久化（key: `forge_state_v2`），Task / DayLog / UserSettings 資料模型（§4）
  - `rolls.js` — tier 加權抽選、EPIC 一次性 roll（§7.5）、LEGACY 次數門檻強化（§7.6）、§7.3 品質計算公式（含金色保底）
  - `animals.js` — 背景動物排程器，含景深/透明度、安靜組（TIRED/NUMB 縮池）、輸入專注模式（§11）
  - `render.js` / `ceremony.js` / `ui.js` — 展覽牆卡片、捕捉層列表、鍛造完成儀式（§8 四階段時序）、全部彈窗與事件綁定
  - `style.css` — 鍛造暗色主題、心情色溫、品質色、儀式動畫
- 更新 `README.md` 反映目前實際完成度與檔案結構
- `docs/sdd.md`（v1）保留作為歷史紀錄，未覆蓋；`docs/sdd-v2.md` 為目前開發依據，本次未修改內容

### 範圍取捨

- 分支僅開放**現代／科技**，仙俠與魔法的開場故事、skin 資料已寫入 `data.js`，UI 上顯示「即將開放」，未來開放時只需在 `data.js` 標記 `mvp:true` 即可上線，不需重寫邏輯
- skin 僅 3 種可抽（霰彈槍／步槍／動力刀），其餘 7 種列於資料表待開放（同上，改個布林值即可）
- 背景動物**全 10 種都做了**（非 SDD 建議的 3 種）——排程器本身是資料驅動的，做 10 種和做 3 種的成本幾乎一樣，於是照 §11.2 完整表格全做，只在預設啟用清單（`ANIMAL_MVP_DEFAULT`）維持 3 種，其餘 7 種可在設定頁自行開啟，更貼近 §11.4 的完整精神
